# 浏览器性能基线

[English](../performance.md) · 简体中文

[文档首页](./README.md) · [媒体兼容性](./compatibility.md)

测试于 2026 年 10 月 30 日进行，设备为 Apple M1 Pro（10 个逻辑核心、16 GiB 内存），使用无头 Chromium 151.0.0.0。结果反映这台开发设备的实测表现。

每个测试通过 `runMediaJob` 串行运行三次，输入和输出均使用 OPFS。统计包含 Worker 启动、元数据检查、编码包复制、排序、输出收尾和临时存储清理。计时范围省略获取和暂存输入以及删除保留的输出。文件和浏览器模块已进入操作系统或浏览器缓存，因此结果反映热缓存条件下的性能。测试未记录 Worker 或进程的内存峰值。

## 测试结果

两份输入均为 150 秒、1280×720、30 fps 的含 B 帧 H.264 视频和 48 kHz AAC 音频，各有 4,500 帧视频。普通输入含 75 个关键帧，长 GOP 输入含 1 个。实测版本对长 GOP 使用磁盘排序。当前复制路径在解码时间信息可用时使用预检建立的解码时间轴，跳过该排序。

| 输入              |      大小 | 三次用时                 |   中位数 |  中位吞吐量 |
| ----------------- | --------: | ------------------------ | -------: | ----------: |
| 普通，GOP 60      | 160.9 MiB | 711.5 / 745.6 / 764.2 ms | 745.6 ms | 215.9 MiB/s |
| 单个 GOP，4500 帧 | 159.3 MiB | 814.1 / 753.2 / 768.9 ms | 768.9 ms | 207.2 MiB/s |

普通输入的检查耗时为 63.9–65.5 ms，收尾耗时为 12.1–16.2 ms。单 GOP 输入的检查耗时为 62.7–63.7 ms，收尾耗时为 370.7–408.0 ms，最后一个分片在收尾时完成排序和临时文件写入。长 GOP 可能将更多工作推迟到结尾，复制进度只能反映部分剩余工作。

测试使用编码包复制模式。主要影响因素包括输入大小、采样数、媒体表结构、GOP 大小、磁盘及缓存表现和可用配额。包数相同时，高码率输入可能得到更高的 MiB/s。多 GB 输入的进程内存、长时间持续吞吐、低端设备和冷缓存 I/O 仍需要独立测量。

## 复现

运行 `pnpm build`，通过本地静态服务器提供仓库文件，然后打开 [`tests/browser/benchmark.html`](../../tests/browser/benchmark.html)。选择输入并运行基准测试。页面在计时前将输入暂存到 OPFS，结束后释放输出及暂存的输入。另可使用[浏览器集成测试页](../../tests/browser/index.html)验证输出与清理行为。

测试素材由 FFmpeg 生成：

```sh
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 \
  -f lavfi -i sine=frequency=1000:sample_rate=48000 -t 150 \
  -c:v libx264 -threads 2 -preset ultrafast -crf 18 -g 60 -bf 2 \
  -c:a aac -movflags +faststart normal.mp4
```

将 `-g 60` 改为 `-g 4500` 可生成长 GOP 输入。使用 `ffprobe` 确认实际关键帧数，编码器设置和内容都可能影响结果。生成的素材未提交到仓库。
