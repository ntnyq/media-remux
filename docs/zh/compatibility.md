## 容器和编码

| 输入                     | 视频编码                                       | 音频编码                                                         | 所选轨道要求                                                                                                           |
| ------------------------ | ---------------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| MP4（含分片 MP4 和 M4A） | H.264、HEVC（`hvc1` 和 `hev1`）、AV1（`av01`） | AAC、MP3、AC-3（`ac-3`）                                         | 每条所选轨道只有一个采样描述，媒体数据位于输入文件内。HEVC 和 AV1 需有各自的解码配置 box，AC-3 需有有效的 `dac3` box。 |
| FLV                      | 标准 AVC                                       | 每帧 960 或 1024 个采样的 AAC-LC，或帧完整且码率由帧头声明的 MP3 | 所选轨道解码配置须保持一致。会拒绝 HE-AAC/SBR，包括隐式声明。                                                          |
| Matroska（MKV）          | H.264                                          | AAC-LC                                                           | 单个 Matroska Segment，所选轨道包含标准 `CodecPrivate`。支持 AAC lacing。                                              |
| MPEG-TS                  | 从带 SPS/PPS 的 IDR 开始的 Annex B H.264       | ADTS 封装的 AAC-LC                                               | 单节目、188 字节传输包，所选轨道 PID 保持一致。                                                                        |

各输入分别选轨。默认选择主视频和主音轨。首轨模式遵循容器顺序，MPEG-TS 取节目映射表中首个识别到的视频和音频轨道；主轨模式优先选择受支持的 MPEG-TS 编码。所选的加密 MP4 轨道和不受支持或加密的 FLV 标签会导致错误。MKV 预检会拒绝所选轨道上的内容编码、旧式轨道偏移、视频 lacing、容器级裁剪、块附加数据、配置变化和非零 `DiscardPadding`。

输出为分片 MP4，纯音频使用 M4A 文件名。HEVC 和 AV1 保留源采样条目类型及解码配置。MPEG-TS H.264 以 `avc3` 写出，保留带内参数集。浏览器是否能播放 MP4 中的 MP3、AC-3 等编码，取决于浏览器和所用播放 API。

## 拼接和音频规范化

复制模式下，所选轨道布局必须匹配。检查包括编解码器字符串、解码器描述字节、视频尺寸、约分后的显示宽高比、色彩配置、视频变换、音频采样率及声道数。保留的视频片段必须从可用关键帧开始。每段接到前一段的呈现结束时间，保留段内偏移和间隙。

核心或 Worker 任务可以设置 `normalizeAudio: true`，将所选单声道或双声道音频编码为连续的 48 kHz 双声道 AAC-LC。编码需要 WebCodecs AAC-LC 编码器和保留音频对应的解码器。视频直接复制编码包。视频配置兼容时，可拼接音频配置不同或缺音轨的片段。有可用音频区间时，以静音填补间隙和缺轨片段。如果裁切后没有任何音频，任务只复制视频并跳过音频编码。[音频规范化拼接示例](./examples.md#任务示例)

## 时间戳和裁切

- 重新封装将最早可播放时间归零。合并遵循[所选时间轴模式](./core.md#combineoptions-和-combinetimeline)。
- 以依赖帧开始的 H.264 MP4 从首个验证含 IDR 图像的同步样本起播。共用时间轴时，会丢弃视频起点之前的音频包。如果首个保留的 MP3 帧依赖被丢弃的数据，需要启用 `normalizeAudio: true`，先解码起点前的音频，再裁切 PCM。如果裁切后没有保留音频包，复制模式输出仅含视频。
- 输出保留解码顺序，包括含 B 帧的视频。时间戳按输出时间刻度取整，采样时长和非负呈现偏移须能用该时间刻度下的无符号 32 位整数表达。
- AV1 的 DTS 与 PTS 相同。起点延迟和视频间隙可在关键帧分片边界表达。预检会拒绝解码时间重叠或间隙后接非关键帧的情况。
- MP4 编辑列表支持可选的前置空 edit，随后是单个播放速率为 1 的媒体 edit。音频可做首尾裁切。复制模式下，首段起点可以落在音频包内，由输出 edit 隐藏裁切部分；后续片段的音频起点落在包内时需要规范化。视频尾部 edit 可缩短最后一个呈现帧。预检会拒绝视频头部裁切、移除整个视频样本的裁切及不支持的编辑序列或速率。
- FLV 的同一轨道要求 DTS 递增。时间戳回绕或不连续时，需提供可独立读取的片段。MKV 的块时间戳为 PTS，读取时会考虑轨道时间刻度和 `CodecDelay`。

## MPEG-TS 分片边界

连续计数器和时间轴都连续、轨道 PID 一致的 MPEG-TS 分片，可按顺序合并为一个 `Blob` 后传给 `remuxMedia`。分片可以切在访问单元内部。读取器会处理 33 位时间戳回绕，并保留共同时间轴中的相对偏移和间隙。基本流分帧缓冲区上限为 32 MiB，超过上限时返回 `UNSUPPORTED_MEDIA_FEATURE`。

使用 [`MpegTsInput`](./core.md#remuxinput-和-mpegtsinput) 记录各分片按 188 字节对齐的绝对起点。显式设置 `allowContinuityCounterReset: true` 后，所选 PID 在后续分片内的首个有效载荷可以重置连续计数器，前提是该包开始合法的新 PES，且上一 PES 完整。普通 `Blob` 和未开启选项的描述符仍严格校验计数器。分片内跳变、续接 PES 时跳变和可检测的截断都会报错。

描述符输入的包级错误可能包含从零开始的分片索引、PID 和绝对字节偏移。如果恰好在允许重置的边界丢失完整 TS 包，而下一个可见包开始合法的新 PES，仅凭字节可能无法区分丢包和重置。需要区分时，可利用可信分片长度或校验值。节目变更和时间戳重置应在提交输入前处理。[构造描述符示例](./examples.md#保留-mpeg-ts-分片边界)
